# Hard Example Analysis

## TL;DR

43 个漏检头部中，**23 个是 `small`，11 个是 `clear_miss`**。`clear_miss` 不是阈值问题，也不是小目标问题：11 个框的中位面积约 **1160 px²**，在 `conf=0.35` 下全部没有同框预测；其中 **9/11 出现在 2–4 个头的多目标帧**，模型通常只检出 0–2 个。

下一步的主线应该是**补多目标数据**，不是继续降 `conf`，也不是只把 `imgsz` 从 640 调大。

## 输入

- 标注：`annotation/`，90 帧，280 框，6 空图
- 漏检集：`hard_examples/`，43 个 head 漏检
- 最终分型：[`review_final.csv`](review_final.csv)
- 汇总：[`review_summary.json`](review_summary.json)
- 基线：[`../PERCEPTION_EVAL.md`](../PERCEPTION_EVAL.md)

## 关键发现 1：clear_miss 不是“阈值低一点就能救”

11 个 `clear_miss`：

- 面积：中位数 **1159.9 px²**，最小 484，最大 3047.6；不是小目标。
- `conf=0.35`：11/11 没有同框预测。
- 把阈值降到 `conf=0.001` 后：
  - 5/11 存在 IoU ≥ 0.5 的候选，但置信度只有 **0.0021–0.0067**；
  - 6/11 即使到 0.001，最大 IoU 仍 < 0.5。

这意味着：

- 降到 0.35 以下没有用：候选在 0.002–0.007，降到那个区间会引入大量误报；
- 也不能简单说“模型定位偏”：有 6/11 连低置信度的几何候选都没有。

## 关键发现 2：clear_miss 集中在多目标帧

11 个 clear_miss 的 GT 头部数量：

```text
1 个头：2 帧
2 个头：4 帧
3 个头：4 帧
4 个头：1 帧
```

即 **9/11 在多目标帧**。逐帧看模型输出：

| 帧 | GT heads | 模型 head 预测 | clear_miss |
|---|---:|---:|---|
| static f5113 | 1 | 0 | #016，面积 3048 |
| slow f9277 | 1 | 0 | #034，面积 2438 |
| slow f11474 | 2 | 0 | #035，面积 744 |
| static f4115 | 2 | 1 | #003 |
| static f16052 | 2 | 1 | #013 |
| slow f9184 | 2 | 1 | #023 |
| static f3189 | 4 | 2 | #002 |
| slow f518 | 3 | 2 | #020 |
| slow f10912 | 3 | 2 | #025 |
| slow f554 | 3 | 2 | #031 |
| slow f1210 | 3 | 2 | #032 |

这不是“漏了画面里唯一的目标”，而是“画面里 2–4 个头，只检出一部分”。

## 关键发现 3：训练集和测试集的目标数量分布不一致

旧训练集 `datasets/cs2_custom/train`：

```text
119 张图：
1 个 head：103 张（86.6%）
2 个 head：16 张（13.4%）
3+ 个 head：0 张
```

pilot test 的 84 张非空图：

```text
1 个 head：43 张（51.2%）
2 个 head：28 张
3 个 head：10 张
4 个 head：3 张
多目标帧：41/84（48.8%）
```

训练集几乎都是单目标，test 有接近一半是多目标。这个分布差异与“多目标帧里只检出部分头”的现象一致，是当前最可疑的域差异来源。

## 关键发现 4：部分 clear_miss 靠近 ROI 边缘

11 个 clear_miss 中，有 3 个框距离 320px ROI 左右边缘 ≤ 6px：

```text
#002  x2=318.06
#025  x2=314.58
#032  x2=317.29
```

这些目标虽然肉眼可见，但可能被 ROI 截断。建议复核时确认：

- 如果头部被 ROI 裁掉一部分，应归 `label_boundary`，不计入模型错误；
- 如果完整可见，保留 `clear_miss`。

#000 已经按 `ROI 边缘` 归为 `label_boundary`，不参与模型改进统计。

| 类型 | 数量 | 归因 | 优先级 |
|---|---:|---|---|

| `occluded` | 1 | 单例，先记录 | 低 |

## 对下一步的含义

### 不建议

1. **不要把 `conf` 降到 0.35 以下**来救 clear_miss：候选在 0.002–0.007，误报会失控。
2. **不要只把 `imgsz` 调大**：clear_miss 的框中位面积 1160 px²，不是小目标；调大输入对 23 个 `small` 可能有用，但解释不了多目标欠检出。
3. **不要直接重训当前 120 张旧数据**：旧数据 86.6% 单目标，重训很可能继续学“一帧一个头”。
4. **不要把 90 帧 test 拿去调参或训练**。

### 建议主线：补多目标数据

这是当前证据最强的方向。

最低数据规格：

- 新增 **≥150 帧**人工标注；
- 其中 **≥60 帧含 2 个及以上 head**；
- 覆盖 3 个场景，至少包含 static / slow / fast 各 1 个新 session；
- **≥20 张空图**；
- 保留 `enemy_head` / `enemy_body` 两类；
- 按 session 分组切分，不能同 session 泄漏；
- 90 帧 pilot test 保持不动。

验收：

- 数据质量检查通过（帧数、标签、ROI、时间戳）；
- 多目标帧数量达标；
- 训练/验证/测试按 session 隔离；
- 先用新数据做一次小规模微调，再和当前 `best.onnx` 在同一 test 对比。

### 可选支线：小目标分辨率实验

只针对 `small` 的 23 个样本，在**独立验证集**上比较 `imgsz=640/960/1280`；不要用 90 帧 test 选型。若没有独立验证集，先补数据，不急着做。

## 结论

- 当前最大问题不是“阈值太高”，而是**多目标欠检出**；
- `clear_miss` 11 个是最高优先级的模型错误，其中 9 个发生在多目标帧；
- 旧训练集 86.6% 单目标，是最可疑的域差异来源；
- 下一步应补多目标标注数据，而不是直接重训或降阈值。
